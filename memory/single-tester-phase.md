用户 2026-09-19 明确交代：**目前 `jplearning.palmsugar.cn` 上只有他一个测试者**，现阶段不用在意用户数据啊什么的问题；**等他明确说「有别的用户了」再开始注意**。

**Why:** 之前几轮我反复就「清旧进度会不会影响学生」「备份够不够」「匿名进度丢了会劝退用户」这类问题提风险、加保险，但线上实际只有他一个人的数据，这些谨慎被高估了——不但没换来安全，反而拖慢迭代、也让他每次都要判断一堆本不存在的风险。

**How to apply:**

- 这个阶段**可以放心做破坏性变更**：改 `word_id`、清表、改 schema、重置线上数据、换 ID 命名空间，都不必为兼容旧数据设计迁移或标记位。
- **不要**再以「会影响用户数据」为由劝阻或加额外保险；该做的正常做。
- 但**改动仍然要如实说明**（改了什么、什么会丢），让他自己判断——这条不变。
- 反过来，**如果哪次改动会毁掉他自己的测试数据、害他重新注册或重新学一遍，还是提一句**，因为那浪费的是他的时间。
- 等他说有真实用户之后，这条作废，恢复按 [[v2.6.1-plan]] 里那套「改教科书词条 ID 或内容会打乱用户进度」的迁移做法（`meta` 表标记位 + 一次性 DELETE）走。

> 已做的备份（[[v2.6.2-plan]]）不受影响，继续跑着——成本为零，且防的是服务器故障而非用户数据。
