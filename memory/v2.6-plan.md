## 两项遗留（别当成已完成）

1. **`fill` / `reading` 题库数据为空**。代码、UI、判分归一化都就绪且单测通过，但没有任何一道真题，所以**新题型的完整答题流程从未被真实数据验证过**。题目格式见 todo-list 第五节。
2. **隐私政策页有可见占位符**：`【备案主体名称，待补充】`，等用户给出 ICP 备案主体名称后替换。

> 另一项遗留 `JWT_SECRET` 用源码默认值的问题，已于同日修复轮换，详见 [[server-config]]。

## 决策（已与用户确认）

| 决策点 | 选择 |
|--------|------|
| 新题型作答方式 | 语法词填空 `fill`、读音练习 `reading` **都用输入框**，答案存 `answer: string[]`（容纳多解） |
| 违禁词屏蔽 | **本期不做**，只做长度 + 字符集校验；预留 `contentFilter(text)` 空实现 |
| 修改昵称 | **直接改 `username`**，不新增 nickname 字段 |
| 访问统计 | busuanzi（布丁统计），用户直接给的代码 |
| 本期范围 | **仅 Web 端**，小程序暂缓 |
| 校验规则位置 | 集中定义在后端，前端实现同一份文案 |

## 校验规则

- 用户名：5~32 字符，仅汉字/平假名/片假名/字母/数字/`_`/`-`
- 密码：≥8 字符，数字/小写/大写/特殊字符四类中至少三类

## 两个必须记住的坑

1. **改 username 后必须重签 JWT**。token 里带着 username，不重签导航栏会一直显示旧名字。
2. **`contentFilter` 是有意留的空实现**。项目存在 UGC 场景（用户名可自定义）却无内容审核，是已知合规缺口；下期接入词库或腾讯云内容安全 API 时只改函数体，不动业务代码。

## 数据库无变更

`users` 表沿用 `id / username / password_hash / openid / created_at`，本期不加列。

## 为什么

**Why:** Web 端刚上线、备案刚结束，先让学生用起来拿反馈，比同时铺双端更划算；违禁词词库的维护成本现阶段高于收益，但调用点必须先留好。
**How to apply:** 继续 v2.6 开发、或决定「现在该补内容审核了吗」时参考本条。相关：[[v2.4-plan]]、[[server-config]]
