# v2.6.2 匿名进度修复 + 数据库备份（2026-09-19）

教科书词库（v2.6.1）部署验收之后，当天追加的一批修复与基建。**已部署。**

## 一、匿名用户进度刷新即丢（真 bug，已修）

**现象**：不登录背几个单词，一刷新全没。

**根因**：`App.vue` 的 `onMounted` 里写着 `if (getToken())` 才调初始化，而那两个初始化函数是**唯一**从 `localStorage` 读回进度的路径。匿名用户内存里 `progressMap` 永远是空的，下一次 `saveAll()` 就把空 map 覆盖写回了本地存储。**错题本和练习历史中的是同一个 bug**（`useExerciseProgress` 写法一模一样）。

**修法**：改成「先用 localStorage 垫底 → 有 token 再用服务端数据覆盖」，`App.vue` 去掉 token 判断无条件调用。函数随之改名 `initSRS` / `initExercise`。

> ⚠️ **最容易踩反的一点：登录/注册成功后不要再调这两个 init。** 新账号服务端是空的，一调就把内存里匿名试用的进度覆盖掉。现状恰好是 login/register 都不调用，所以匿名进度会在下次 `saveAll()` 时随登录态推到服务端，**等于天然继承**。要动登录流程先看 `useSRS.ts` 里 `initSRS` 的注释。

**退出登录**：`App.vue` 与 `UserCenter.vue` 各有一份重复的 `handleLogout`，都补了「退出后重新 init 读回本机数据」，否则内存清空后随手一点就把本地匿名进度冲掉。

> ⚠️ **小程序端是反的**：`codes/miniprogram/src/pages/login/login.vue` 在登录后**会**调 init，踩的是「匿名进度被新账号覆盖」。小程序暂缓上线故未改，恢复开发时要一并处理。

## 二、`/user` 漏了 `requiresAuth`

未登录能直接进用户中心。已补。现在 `/word`、`/exercise`、`/user` 都要求登录。

**三个路由约定别搞错**：
- 首页 `/` **保持公开**（有意为之，匿名可看欢迎页与入口卡片，当门面）
- `/privacy`、`/contact` **必须公开**（备案要求），绝不能加 `requiresAuth`

## 三、数据库备份（此前线上零备份）

线上库跑在 WAL 模式，**主库文件只有 4KB，真实数据压在 190KB 的 `-wal` 里** —— 直接 `cp` 拿到的是不完整快照。

`server/scripts/backup-db.mjs`：在线备份 API → `integrity_check` + 行数校验 → 转非 WAL 单文件 → 轮转留 14 份。cron 每天 03:17，产出 `/opt/japanese-learning/backups/`，日志 `/var/log/jplearning-backup.log`。

两个设计点值得记住：
- **校验不过就删掉备份并非零退出**。坏备份比没备份更危险——它会让人以为自己有退路
- **必须转成非 WAL 单文件**。不转的话校验时会在旁边生成 `-wal`/`-shm`，而轮转只认 `.db`，副文件会无限堆积（第一版实测才发现）

> 部署指南原来那条 `sqlite3 ... ".backup"` **在服务器上跑不通**——服务器没装 `sqlite3` 这个命令。见 [[server-config]] 第 9 条。

⚠️ **同盘备份防不了磁盘损坏**，只能防误删和写坏。异地容灾（COS / 本机拉取）尚未做。

## 四、讨论过但决定不做

- **TTS 发音**：暂缓。全项目零音频代码；难点是微信内置浏览器对 `speechSynthesis` 支持不稳，学生从微信进基本得预生成音频。先补数据、打磨细节、上线看效果，之后再议
- **关掉匿名使用**：保持现状（首页当门面）
- **注册门槛**（用户名 5~32、密码 ≥8 且四类含三类）：对初学者偏高，但先不动，等真实反馈
