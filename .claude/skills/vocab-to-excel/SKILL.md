# 日语单词表图片 → Excel

把课本单词表的照片整理成 5 列的 Excel，输出到 `docs/vocabulary_files/<母文件夹名>.xlsx`。

## 输出格式

一个 sheet，5 列，顺序固定：

| 日语 | 读音 | 声调 | 词性 | 中文意思 |
|---|---|---|---|---|
| 留学生 | りゅうがくせい | ③④ | [名] | 留学生 |
| 木村 | きむら | ⓪ | [名（専）] | 木村（姓氏） |
| こんにちは | こんにちは | ⑤ | | 你好 |

- **命名**：按图片所在的**母文件夹**命名，不是图片名。`.../UNIT 1/*.jpg` → `UNIT 1.xlsx`
- **顺序**：按页面顺序排。生词表 → 生词表续表 → 补充单词表 → 补充单词表续表，依次往下接
- **多张表合并**在同一 sheet，不加来源列

## 数据流

OCR 结果先写成 JSON，再交给脚本生成 Excel。**不要直接写 xlsx。**

```
codes/vocab_data/<母文件夹名>.json      ← 你写这个
        ↓  python codes/build_vocab_excel.py "<母文件夹名>"
docs/vocabulary_files/<母文件夹名>.xlsx  ← 脚本生成
```

JSON 格式：数组，每行 5 个元素，顺序同上面的列序，缺失填空字符串。

```json
[
  ["わたし", "", "①", "[代]", "我"],
  ["留学生", "りゅうがくせい", "③④", "[名]", "留学生"]
]
```

脚本会校验每行必须是 5 列，并对已有单元做增量重生成（改 JSON 重跑即可，不要手改 xlsx）。

新增单元后要跑一次**跨单元去重**：

```bash
python codes/dedup_vocab.py --dry-run   # 先看会删哪些
python codes/dedup_vocab.py             # 实际删除，然后重跑 build_vocab_excel.py
```

规则：**日语 + 读音都相同即为重复**，只保留单元号小的那个（UNIT 1 优先于 UNIT 5），单元内重复保留首次出现。纯假名词的读音按回填后的值比较，跟 Excel 里看到的一致。

## 读取图片（关键步骤，别偷懒）

课本照片有 3000~4000 px 宽。**整张直接读会看错声调** —— `⓪`（零调）和 `①` 在小图上几乎分不出来，`③`/`⑧`、`⑤`/`⑥` 同理，而这几个错一个词就废了。

必须两步走，用 `codes/slice_for_ocr.py`：

```bash
# 1. 整图缩略，只看版面结构：有几张表、表头在哪、哪些是语法页要跳过
python codes/slice_for_ocr.py "assets/.../IMG_xxx.jpg" --preview 1300 --out .tmp_ocr

# 2. 按第 1 步定位到的表格区域，原图满分辨率裁剪 + 横向切 2~3 条，逐条精读
python codes/slice_for_ocr.py "assets/.../IMG_xxx.jpg" --box 200,900,2900,3650 --bands 3 --out .tmp_ocr
```

第 2 步的 `--box` 从第 1 步的缩略图按比例换算回原图坐标。切出来的每条裁剪图不要超过 ~2500 px 宽，否则照样看不清。

## 提取规则

课本表头是「汉字(假名读音) 声调 | 词性 | 词义(中文)」，要拆成 5 列：

- **日语**：汉字/假名本体，**不含**括号里的读音
- **读音**：括号里的假名。原词只写了假名（没括号）时留空 —— 脚本会自动填成「日语」本身
- **声调**：圆圈数字原样照抄，可能是一个 `①` 也可能是多个 `③④` `⑤⑦⑧`。**没有就留空**
- **词性**：第二列原文，**保留方括号** `[名]` `[名（専）]` `[自動1]`。没有就留空
- **中文意思**：第三列原文

细节：

- 括号统一用**全角** `（）`，跟书上一致：`[名（専）]`、`王（姓氏）`
- 中文逗号用全角 `，`，分号用 `；`：`前辈；学长`、`书，书籍`
- **跨行折行的单元格要拼回一行**。比如
  `よろしくお願いします(よろしくおねが` / `いします)` 是同一个词，
  要还原成 日语=`よろしくお願いします`、读音=`よろしくおねがいします`
- **续表**（标了"（续表）"的页）是上一页表格的延续，接着往下排，不要当成新表重开

## 跳过什么

- 语法/句型页、练习页、课后小知识 —— 只要**单词表**（生词表、补充单词表）
- 一页里可能同时有生词表和补充单词表，**两张都要提取**

## 完成后核对

Windows 终端是 GBK，直接 print 日文会乱码。用 openpyxl 读回、dump 成 UTF-8 文本文件再 Read：

```bash
python -c "
import openpyxl, io
ws = openpyxl.load_workbook('docs/vocabulary_files/UNIT 1.xlsx').active
out = io.open('.dump.txt','w',encoding='utf-8')
for i,r in enumerate(ws.iter_rows(values_only=True),1):
    out.write(str(i).rjust(3)+' | '+' | '.join('' if v is None else str(v) for v in r)+'\n')
out.close()
"
```

逐行比对原图，然后删掉 `.tmp_ocr/` 和 `.dump.txt`。

汇报时给出：**词条数** + **你自己拿不准的地方**（书上印得模糊、格式有歧义、跟前文不一致的），让用户确认。不要只报"完成了"。

## 已确认的先例（保持一致）

- 纯假名词的读音 = 单词本身，例如 `わたし / わたし`
- 声调为 `⓪` 的词（木村、鈴木、先輩、こちら、学生、日本語、田中、林、大学…）是零调，**不要写成 `①`**
- **一律照书抄，不要按词典"纠正"**。这本书多处声调与常规词典不符（`ここ/そこ/あそこ` 印 ⓪、`おはようございます` 印 ⑧、`レモン` 印 ①⓪、`言う/教える/乗る` 印 ⓪）。已复核确认是书上原样，不是读错 —— 原样录入。
- 一词多声调时**按书上印刷顺序**抄，不排序、不去重：`④⓪`、`①⓪`、`③④`、`⑤⑦⑧`
- 词性里的间隔号用 `・`（U+30FB）：`[名・他動3]`、`[代・名]`

## 两个已知的坑

**1. ⓪ / ① 是头号错误源。** 缩略图上零调极易误看成 ①，一个单元就可能错二十几个。**必须走满分辨率切条那一步**，声调列建议再单独窄条放大一次。（实际批量中，UNIT 10 一个单元靠这步救回 22 个误读。）

**2. 书本的「单元」≠ 用户的 UNIT 文件夹。** 这本书的「第X単元」横跨多课，所以 `UNIT 5/` 里的页面眉可能印着「第二单元」、`UNIT 13/` 印着「第四单元」—— 这是正常的，**不是错拍，不用改归属**。

## 待用户拍板的悬而未决项

以下是批量过程中出现、规则没覆盖、**需要用户确认**的情况，遇到同类问题时先问再改：

- `～` 开头词的读音口径不统一：有括号的（`～人（にん）` → `にん`）和没括号的（`～さん` → `～さん`，波浪号原样保留）会得出不同结果
- 短语类条目的读音：`え？`、`どうしました？` 按规则会回填成 `え？`、`どうしました？`，看着像重复
- 纯假名词但书上没印声调/词性的（`すみません`、`ありがとうございます` 等），是否要按词典补
