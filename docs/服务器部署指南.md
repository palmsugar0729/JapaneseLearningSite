## 0. 线上架构速查

先看这一页，日常操作基本都在这里。

| 项 | 值 |
|----|-----|
| 访问地址 | `https://jplearning.palmsugar.cn` |
| 代码根目录 | `/opt/japanese-learning/JapaneseLearningSite/`（**属 root**） |
| 前端 web root | `/opt/japanese-learning/JapaneseLearningSite/codes/web/dist`（**属 ubuntu**） |

## 1. 日常部署（99% 的情况看这节）

> ⚠️ **服务器连不上 GitHub**（已实测），所以**不能用 `git pull` 部署**，一律走 `scp` 传文件。
> 本机直连 GitHub 往往也不通（要走代理），所以「本地 commit + 手动 push」与「部署到服务器」是**两件独立的事**，别指望 push 完服务器就自己更新了。

### 1.1 只改前端

```bash
# 本地
cd codes/web && npm run build
tar czf /tmp/jp-dist.tgz dist
scp /tmp/jp-dist.tgz jplearning:/tmp/

# 服务器：备份旧 dist，换上新的
ssh jplearning
cd /opt/japanese-learning/JapaneseLearningSite/codes/web
mv dist dist.bak-$(date +%Y%m%d-%H%M%S)
tar xzf /tmp/jp-dist.tgz
chown -R ubuntu:ubuntu dist
```

前端目录属 `ubuntu`，**不需要 sudo**。

### 1.2 只改后端

`server/src/` 属 **root**，`ubuntu` 直接写会被拒。必须先传 `/tmp/` 再 `sudo cp`：

```bash
# 本地：把改动的文件传到 /tmp
scp server/src/routes/auth.ts server/src/validation.ts jplearning:/tmp/

# 服务器：备份 → 安装 → 保持属主 → 重启
ssh jplearning
SRC=/opt/japanese-learning/JapaneseLearningSite/server/src
sudo cp $SRC/routes/auth.ts $SRC/routes/auth.ts.bak-$(date +%Y%m%d-%H%M%S)
sudo cp /tmp/auth.ts       $SRC/routes/auth.ts
sudo cp /tmp/validation.ts $SRC/validation.ts
sudo chown root:root $SRC/routes/auth.ts $SRC/validation.ts
sudo chmod 644       $SRC/routes/auth.ts $SRC/validation.ts

export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH
sudo env PATH=$PATH pm2 restart japanese-api
```

> ⚠️ `pm2` **不在 ubuntu 的任何 PATH 里**（连 `bash -lc` 都找不到），因为它装在 **root** 的 nvm 下。必须写成上面那样显式指定 node 路径。裸跑 `pm2` 会报 `/usr/bin/env: 'node': No such file or directory`，**看起来像 pm2 没装，其实不是**。

### 1.3 部署前先比对差异（推荐）

改后端时最容易「以为只有一处改动」。传之前先确认差异范围，避免误传或漏传：

```bash
# 本地
find server/src -type f -name "*.ts" | sort | xargs md5sum
# 服务器
ssh jplearning 'cd /opt/japanese-learning/JapaneseLearningSite/server/src && find . -type f -name "*.ts" | sort | xargs md5sum'
```

两边对一遍，就知道到底该传哪几个文件。

### 1.4 部署后验证

```bash
# 从本地打公网（不是在服务器上打 127.0.0.1，原因见 4.2）
curl -s https://jplearning.palmsugar.cn/api/health          # {"ok":true,...}
curl -s -o /dev/null -w "%{http_code}\n" https://jplearning.palmsugar.cn/
curl -s -o /dev/null -w "%{http_code}\n" https://jplearning.palmsugar.cn/beian.png

# 服务器上确认进程没崩
ssh jplearning 'export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH
  sudo env PATH=$PATH pm2 list
  sudo env PATH=$PATH pm2 logs japanese-api --lines 20 --nostream'
```

判断标准：PM2 状态 `online`、`unstable restarts` 为 0、重启次数没有持续暴涨（次数会随历史累积，关键是**不涨**）。

- 前端没问题：`/` 返回的新 bundle 文件名与本地 `codes/web/dist/assets/index-*.js` 一致
- 后端没问题：新加的接口**返回 401/400 而不是 404**（404 = 路由根本没注册上，说明文件没传对）

### 1.5 回滚

每次部署都留了带时间戳的备份：

```bash
# 前端
cd /opt/japanese-learning/JapaneseLearningSite/codes/web
mv dist dist.broken && mv dist.bak-<时间戳> dist

# 后端
sudo cp .../server/src/routes/auth.ts.bak-<时间戳> .../server/src/routes/auth.ts
sudo env PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH pm2 restart japanese-api
```

线上备份清单（可择机清理）：

```bash
ls -d /opt/japanese-learning/JapaneseLearningSite/codes/web/dist.bak-*
sudo ls /opt/japanese-learning/JapaneseLearningSite/server/src/routes/*.bak-*
```

## 2. 首次部署（从零重建时看这节）

> 已经部署过，日常不用看。换服务器 / 灾后重建时参考。

### 2.1 基础环境

```bash
sudo apt update && sudo apt upgrade -y
sudo timedatectl set-timezone Asia/Shanghai
sudo apt install -y curl wget git vim ufw build-essential

# 防火墙：只开 22/80/443
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

> ⚠️ **不要放行 3001**。后端只通过 nginx 反代访问，不直接暴露。

### 2.2 Node.js + PM2

PM2 要处理开机自启，装到 **root** 下（线上现状如此）：

```bash
sudo -i
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 20 && nvm alias default 20
npm install -g pm2
pm2 startup          # 执行它输出的那行 sudo 命令
# 会生成 pm2-root.service；确认已启用：
systemctl is-enabled pm2-root.service
```

### 2.3 nginx

```bash
sudo apt install -y nginx
sudo systemctl enable --now nginx
```

站点配置见第 3 节。

### 2.4 拉代码 + 起后端

服务器连不上 GitHub，所以从**本机 scp 上传**：

```bash
# 本机
cd d:/WorkSpace/projects/mix/JapaneseLearning
scp -r server/ jplearning:/opt/japanese-learning/JapaneseLearningSite/
```

```bash
# 服务器
sudo -i
cd /opt/japanese-learning/JapaneseLearningSite/server
mkdir -p data                    # better-sqlite3 需要，否则报 "directory does not exist"
npm install
npx tsx src/index.ts             # 看到 "[server] running at http://localhost:3001" 即成功，Ctrl+C 停
pm2 start "npx tsx src/index.ts" --name japanese-api

```

### 2.5 前端

```bash

cd codes/web && npm run build
scp -r dist/ jplearning:/tmp/
# 服务器：放到 web root（属 ubuntu，不用 sudo）
```

## 3. nginx 配置

真实生效的配置（`/etc/nginx/sites-available/japanese-api`，仓库里有副本 `nginx-jplearning.conf`）：

```nginx
server {
    server_name jplearning.palmsugar.cn;

    root /opt/japanese-learning/JapaneseLearningSite/codes/web/dist;
    index index.html;

    access_log /var/log/nginx/japanese-access.log;
    error_log  /var/log/nginx/japanese-error.log;

    # nginx 默认只压 text/html，必须显式补全，否则 JS 不压缩
    gzip_types text/html text/plain text/css application/json application/javascript
               application/x-javascript text/javascript text/xml application/xml
               application/xml+rss image/svg+xml;
    gzip_comp_level 6;
    gzip_min_length 1024;
    gzip_vary on;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 带 hash 的静态资源可安全长期缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=2592000, immutable";
        try_files $uri =404;
    }

    # SPA 回退（Vue Router 需要）
    location / {
        try_files $uri $uri/ /index.html;
    }

    listen 443 ssl;                    # managed by Certbot
    ssl_certificate     /etc/letsencrypt/live/jplearning.palmsugar.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/jplearning.palmsugar.cn/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    if ($host = jplearning.palmsugar.cn) { return 301 https://$host$request_uri; }
    listen 80;
    server_name jplearning.palmsugar.cn;
    return 404;                        # managed by Certbot
}
```

改完必须：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

> 🔑 **80 端口那个 server 块是 `return 404`** —— 这是本指南里最容易让人误判的一条，务必读 4.2。

## 4. 故障排查

### 4.1 PM2 相关

```bash
export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH
sudo env PATH=$PATH pm2 list
sudo env PATH=$PATH pm2 logs japanese-api --lines 50 --nostream
sudo env PATH=$PATH pm2 restart japanese-api
```

**`pm2: command not found` 不是没装** —— 是 PATH 问题，见 1.2。

### 4.2 ⚠️ `curl http://127.0.0.1/api/health` 返回 404（最常见的误判）

**不要用这个命令验证后端。** nginx 里针对 `jplearning.palmsugar.cn` 的 80 端口 server 块是 `return 404`，而你用 IP 请求时 `Host` 是 `127.0.0.1`，会命中这个块，于是拿到一个**来自 nginx 的 404 页面**。

这看起来像「后端挂了」，其实后端好得很。要验证请走公网域名：

```bash
curl -s https://jplearning.palmsugar.cn/api/health
```

要在服务器本地直连后端，绕过 nginx：

```bash
curl -s http://127.0.0.1:3001/api/health
```

### 4.3 nginx 502 Bad Gateway

说明 nginx 连不上 Node 后端：

```bash
ss -tlnp | grep 3001        # 端口在监听吗
export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH
sudo env PATH=$PATH pm2 status
```

### 4.4 服务器上 `git status` 报 dubious ownership

仓库属 root，用 sudo 并先加白名单：

```bash
sudo git config --global --add safe.directory /opt/japanese-learning/JapaneseLearningSite
```

### 4.5 scp 报 Permission denied

目标目录属 root。传到 `/tmp/` 再用 `sudo cp`（见 1.2）。

### 4.6 网站整体打不开

```bash
sudo systemctl status nginx
export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH; sudo env PATH=$PATH pm2 status
sudo nginx -t
sudo tail -50 /var/log/nginx/japanese-error.log
# 再去腾讯云控制台 → 轻量应用服务器 → 防火墙，确认 22/80/443 放行
```

## 5. 环境变量与密钥

后端读取以下环境变量，**均为可选，但生产环境不该用默认值**：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3001` | 监听端口 |
| `JWT_SECRET` | `japanese-learning-dev-secret` | ⚠️ **签发 token 的密钥**，线上已是随机值 |
| `WX_APPID` | 空 | 微信小程序 AppID |
| `WX_SECRET` | 空 | 微信小程序 AppSecret |

> ⚠️ 线上**不落 `.env` 文件**（`package.json` 里也没有 `dotenv`，只能靠进程环境变量注入），密钥统一放 `/root/.jplearning-secrets.env`（权限 600，属主 root）。

```bash
set -a; . /root/.jplearning-secrets.env; set +a
sudo env PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH pm2 restart japanese-api --update-env
sudo env PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH pm2 save
```

> ⚠️ **`pm2 save` 不能省。** 注入的环境变量只活在当前进程里，不 save 的话主机重启（`pm2-root.service` 按 dump 恢复）就会**静默退回源码默认值**，等于漏洞复活。
>
> ⚠️ `WX_SECRET` **绝不能写进任何会被提交的文件**。微信登录因 `WX_APPID`/`WX_SECRET` 为空而暂不可用（符合当前预期）。

### 5.1 JWT_SECRET 轮换记录（2026-09-15）

**为什么换：** 线上此前一直没有密钥文件，后端回退到源码里硬编码的 `'japanese-learning-dev-secret'`，而源码在 GitHub 上公开 —— 任何看过源码的人都能伪造任意用户的登录态。

**怎么做：** 服务器上 `openssl rand -hex 32` 生成 64 位密钥写入密钥文件，再按上面的命令注入 PM2 并 `save`。

**怎么验证**（用受鉴权保护的 `GET /api/progress/srs` 做探针，可在服务器上跑）：

| 用哪把密钥签 token | 期望 | 实测 |
|-------------------|------|------|
| 旧默认值 `japanese-learning-dev-secret` | 401 拒绝 | ✅ 401 |
| 密钥文件里的新值 | 200 放行 | ✅ 200 |
| 不带 token | 401 | ✅ 401 |

并确认 `/root/.pm2/dump.pm2` 中已含新密钥且与密钥文件一致（长度 64、非默认值），`systemctl is-enabled pm2-root` 为 `enabled`，**保证重启不退回默认值**。

> 回滚：旧值就是源码默认值，把 `JWT_SECRET` 从环境里去掉即可 —— 但那等于恢复漏洞，只用于临时排障。

## 6. 维护

### 常用命令

```bash
# PM2（注意 PATH）
export PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH
sudo env PATH=$PATH pm2 list | logs japanese-api | restart japanese-api | save

# Nginx
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl restart nginx

# 服务器状态
df -h; free -h; sudo ufw status
```

### 数据库备份

> ⚠️ 数据库跑在 **WAL 模式**，直接 `cp` 主库文件可能拿到不完整快照。用 SQLite 的在线备份，或至少把 `-wal`/`-shm` 一起带走：

```bash
sudo sqlite3 /opt/japanese-learning/JapaneseLearningSite/server/data/japanese.db \
  ".backup '/opt/japanese-learning/JapaneseLearningSite/server/data/backup-$(date +%Y%m%d).db'"

# 保留最近 7 天
sudo find /opt/japanese-learning/JapaneseLearningSite/server/data/ -name "backup-*.db" -mtime +7 -delete
```

## 修订说明（2026-09-15）
