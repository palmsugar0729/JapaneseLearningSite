## 2026-08-13 — 服务器部署完成

## 一、今日完成

| # | 事项 | 说明 |
|---|------|------|
| 1 | 服务器环境搭建 | Ubuntu 24.04 + 时区 + 防火墙（22/80/443） |
| 2 | Node.js 20 + nvm + PM2 | nvm 管理版本，PM2 开机自启 |
| 3 | Nginx 反向代理 | 80 端口 → localhost:3001 |
| 4 | 后端代码部署 | `/opt/japanese-learning/JapaneseLearningSite/` |
| 5 | 后端 PM2 守护 | `japanese-api` 进程稳定 online |
| 6 | DNS 解析 | `jplearning.palmsugar.cn` → `124.221.0.238` |
| 7 | 外网验证通过 | `http://jplearning.palmsugar.cn/api/health` 返回 ok |

## 二、踩坑记录

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | `apt` 报 Permission denied | 免密连接是普通用户，非 root | `sudo -i` 切 root |
| 2 | `sshd_config` 提示升级 | 腾讯云定制过 SSH 配置 | 选"保持当前版本" |
| 3 | `npm install` 报 ENOENT | git clone 没加 `.`，多套一层文件夹 | 用 `/JapaneseLearningSite/server/` 路径 |
| 4 | 数据库 directory not exist | better-sqlite3 需要 data 目录 | `mkdir -p data` |
| 5 | PM2 报 Permission denied | `--interpreter npx -- tsx` 写法错误 | `pm2 start "npx tsx src/index.ts" --name japanese-api` |
| 6 | 外网 502 | 未配 Nginx 反向代理，直接访问 3001 | 配 Nginx 走 80 端口 |

## 三、关键决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 部署方式 | git clone 到 `/opt/` | 更新方便，git pull 即可 |
| 2 | 对外端口 | 只暴露 80/443，3001 内部用 | 安全，避免后端直接暴露 |
| 3 | 域名 | `jplearning.palmsugar.cn` 子域名 | 主域名留给其他项目 |

## 二、关键决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 技术栈 | uni-app (Vue 3) | 一套代码编译微信小程序 + H5，单人维护成本最低 |
| 2 | 数据策略 | 开发期本地 N5，上线后 API 按需 | 小程序 2MB 包限制，全量 16k 词无法打包 |
| 3 | 存储层 | `uni.getStorageSync/setStorageSync` | 接口不变，内部实现从 localStorage 切换 |
| 4 | HTTP 客户端 | `uni.request` | 替代 fetch，兼容小程序网络层 |
| 5 | 样式方案 | 白色卡片 + 浅绿底色 | 小程序不支持 backdrop-filter 玻璃拟态 |
| 6 | 登录方案 | 小程序微信登录 + Web 账号密码 | 个人可用微信登录，Web 保持现有系统 |
| 7 | 服务器系统 | Ubuntu 24.04 LTS | Node.js 生态最友好，apt 直接装 |

## 二、关键决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 存储架构 | API+SQLite / localStorage 双模式 | 登录用户服务端持久化，未登录用户不丢数据 |
| 2 | 图表渲染 | ECharts 按需引入 | 减小打包体积 |
| 3 | SRS 单词级 | SM-2 | 算法简单成熟，16k 词规模够用 |
| 4 | 教科书单词 | 复用 SRS 引擎 | 通过 source/unit 字段区分，不重复造轮子 |
| 5 | token 响应式 | `_token` 用 Vue `ref` | 退出登录 UI 立即响应 |
| 6 | level 字段注入 | API 层从文件名提取 | JSON 文件内无 level，避免数据冗余 |
