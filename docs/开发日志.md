## 二、关键决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 技术栈 | uni-app (Vue 3) | 一套代码编译微信小程序 + H5，单人维护成本最低 |
| 2 | 数据策略 | 开发期本地 N5，上线后 API 按需 | 小程序 2MB 包限制，全量 16k 词无法打包 |
| 3 | 存储层 | `uni.getStorageSync/setStorageSync` | 接口不变，内部实现从 localStorage 切换 |
| 4 | HTTP 客户端 | `uni.request` | 替代 fetch，兼容小程序网络层 |
| 5 | 样式方案 | 白色卡片 + 浅绿底色 | 小程序不支持 backdrop-filter 玻璃拟态 |
| 6 | 登录方案 | 小程序微信登录 + Web 账号密码 | 个人可用微信登录，Web 保持现有系统 |
| 7 | 服务器系统 | Ubuntu 24.04 LTS | Node.js 生态最友好，apt 直接装 |

## 二、关键决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 存储架构 | API+SQLite / localStorage 双模式 | 登录用户服务端持久化，未登录用户不丢数据 |
| 2 | 图表渲染 | ECharts 按需引入 | 减小打包体积 |
| 3 | SRS 单词级 | SM-2 | 算法简单成熟，16k 词规模够用 |
| 4 | 教科书单词 | 复用 SRS 引擎 | 通过 source/unit 字段区分，不重复造轮子 |
| 5 | token 响应式 | `_token` 用 Vue `ref` | 退出登录 UI 立即响应 |
| 6 | level 字段注入 | API 层从文件名提取 | JSON 文件内无 level，避免数据冗余 |
